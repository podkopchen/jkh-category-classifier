# Category DeepPavlov v1.0.0

Локальный проект для проверки модели классификации обращений ЖКХ на реальных Excel-выгрузках.

Модель принимает текст обращения из столбца **«Описание проблемы»**, определяет категорию проблемы и сравнивает результат с исходной категорией из столбца **«Категория»**.

Проект нужен не только для получения общего процента точности, но и для нормального анализа качества модели: поиска слабых категорий, частых пар ошибок, уверенных неправильных предсказаний и спорной исходной разметки.

## Возможности

Скрипт `predict_excel.py` выполняет полный цикл проверки модели:

1. Загружает Excel-файл с обращениями.
2. Берет текст обращения из столбца `Описание проблемы`.
3. Загружает обученную модель классификации.
4. Предсказывает категорию обращения.
5. Сравнивает предсказание с исходной категорией из столбца `Категория`.
6. Сохраняет Excel-отчеты для анализа качества.

В результате создаются файлы:

- `predictions.xlsx` — все предсказания модели;
- `errors.xlsx` — только ошибки;
- `high_confidence_errors.xlsx` — ошибки с высокой уверенностью;
- `classification_report.xlsx` — метрики по категориям;
- `confusion_matrix.xlsx` — матрица ошибок;
- `error_pairs.xlsx` — самые частые пары ошибок.


## Настройки скрипта

Основные настройки находятся в начале `predict_excel.py`.

```python
EXCEL_PATH = BASE_DIR / "data" / "jkh_requests.xlsx"
MODEL_DIR = BASE_DIR / "predict_model"
OUTPUT_DIR = BASE_DIR / "outputs"

TEXT_COLUMN = "Описание проблемы"
TRUE_LABEL_COLUMN = "Категория"

MAX_LENGTH = 128
BATCH_SIZE = 128

HIGH_CONFIDENCE_THRESHOLD = 90.0
EXCLUDED_FROM_KNOWN_ACCURACY = {"Другое"}
```

Описание параметров:

| Параметр | Назначение |
|---|---|
| `EXCEL_PATH` | Путь к исходной Excel-таблице |
| `MODEL_DIR` | Путь к папке с моделью |
| `OUTPUT_DIR` | Папка для сохранения отчетов |
| `TEXT_COLUMN` | Название столбца с текстом обращения |
| `TRUE_LABEL_COLUMN` | Название столбца с исходной категорией |
| `MAX_LENGTH` | Максимальная длина текста для модели |
| `BATCH_SIZE` | Количество строк, обрабатываемых за один батч |
| `HIGH_CONFIDENCE_THRESHOLD` | Порог уверенности для отдельного файла с уверенными ошибками |
| `EXCLUDED_FROM_KNOWN_ACCURACY` | Категории, исключаемые из дополнительной честной метрики |

Если скрипт работает на CPU, обработка большого Excel-файла может занять длительное время.

Базовые параметры:

```python
MAX_LENGTH = 128
BATCH_SIZE = 128
```

Если не хватает памяти, уменьшите батч:

```python
BATCH_SIZE = 64
```

Если памяти достаточно и нужно ускорить обработку, можно попробовать:

```python
BATCH_SIZE = 256
```

Для быстрой тестовой проверки можно временно ограничить количество строк после загрузки Excel:

```python
work_df = work_df.head(1000).copy()
```

## Описание выходных файлов

### `predictions.xlsx`

Основной файл со всеми строками.

| Колонка | Описание |
|---|---|
| `Проблема` | Текст обращения |
| `Изначальная Категория` | Категория из исходной Excel-таблицы |
| `ИИ категория` | Категория, предсказанная моделью |
| `Уверенность (%)` | Уверенность модели в процентах |
| `Совпало` | Совпала ли категория модели с исходной категорией |

### `errors.xlsx`

Файл только с ошибками модели.

Сюда попадают строки, где:

```text
Изначальная Категория != ИИ категория
```

Файл отсортирован по уверенности модели. Сверху находятся ошибки, где модель была наиболее уверена в неправильном ответе.

### `high_confidence_errors.xlsx`

Файл с ошибками, где уверенность модели больше или равна заданному порогу.

По умолчанию:

```python
HIGH_CONFIDENCE_THRESHOLD = 90.0
```

Этот файл особенно важен для анализа, потому что ошибки с высокой уверенностью часто показывают:

1. системную ошибку модели;
2. спорную исходную разметку;
3. категорию, которой нет среди классов модели;
4. пересечение нескольких похожих категорий.

### `error_pairs.xlsx`

Файл с самыми частыми парами ошибок.

Пример:

| Изначальная Категория | ИИ категория | Количество |
|---|---:|---:|
| Сантехника | Кровля | 112 |
| Электрика | Управление освещением подъезда | 108 |
| Системы ДУ и ППА | Вентиляция | 45 |

Это один из самых полезных файлов для доработки модели.

Он отвечает на вопрос:

```text
Какие категории модель путает чаще всего?
```

### `classification_report.xlsx`

Отчет по метрикам для каждой категории.

| Метрика | Что означает |
|---|---|
| `precision` | Насколько точны предсказания этой категории |
| `recall` | Какую долю реальных объектов категории модель нашла |
| `f1-score` | Баланс precision и recall |
| `support` | Количество строк этой категории в исходной таблице |

Как читать отчет:

- низкий `precision` — модель слишком часто ошибочно выбирает эту категорию;
- низкий `recall` — модель часто пропускает эту категорию;
- низкий `f1-score` — категория в целом проблемная;
- маленький `support` — по категории мало примеров, метрика может быть нестабильной.

### `confusion_matrix.xlsx`

Матрица ошибок.

Строки — реальные категории из Excel.

Колонки — категории, предсказанные моделью.

Пример чтения:

```text
true: Сантехника
pred: Кровля
112
```

Это значит, что 112 строк с исходной категорией `Сантехника` модель отнесла к `Кровля`.

## Как интерпретировать качество

Не стоит ориентироваться только на общий accuracy.

Скрипт печатает две основные метрики:

```text
Accuracy
Accuracy без исключенных категорий
```

`Accuracy` — точность на всех строках.

`Accuracy без исключенных категорий` — точность без категорий, которые модель не знает или которые не нужно учитывать в честной оценке.

Например, если в исходной таблице есть категория `Другое`, а модель не обучалась ее предсказывать, все такие строки автоматически будут считаться ошибками.

В скрипте исключенные категории задаются так:

```python
EXCLUDED_FROM_KNOWN_ACCURACY = {"Другое"}
```

Если не нужно исключать категории, можно поставить:

```python
EXCLUDED_FROM_KNOWN_ACCURACY = set()
```

## Рекомендации по анализу ошибок

Для доработки модели наиболее полезны три файла:

```text
outputs/error_pairs.xlsx
outputs/high_confidence_errors.xlsx
outputs/classification_report.xlsx
```

Рекомендуемый порядок анализа:

1. Открыть `error_pairs.xlsx`.
2. Найти самые частые пары ошибок.
3. Открыть `high_confidence_errors.xlsx`.
4. Проверить ошибки, где модель была уверена на 95–100%.
5. Определить, где ошиблась модель, а где исходная категория спорная или ошибочная.
6. Добавлять в обучение только проверенные ошибки.

## Рекомендации по дообучению

Не рекомендуется автоматически добавлять все ошибки обратно в обучение.

В файле `errors.xlsx` могут быть:

- реальные ошибки модели;
- ошибки исходной разметки;
- спорные случаи;
- категории, которых нет в модели;
- обращения, где в тексте смешано несколько проблем.

Лучший цикл доработки:

1. Запустить `predict_excel.py`.
2. Открыть `outputs/error_pairs.xlsx`.
3. Выбрать самые частые пары ошибок.
4. Открыть `outputs/high_confidence_errors.xlsx`.
5. Вручную проверить спорные строки.
6. Разделить ошибки на группы:
   - модель ошиблась;
   - исходная категория спорная;
   - исходная категория ошибочная;
   - категория отсутствует в модели.
7. В обучение добавлять только проверенные строки.
8. Добавлять не только очевидные примеры, а контрастные пары.
9. Переобучить модель.
10. Снова прогнать Excel и сравнить метрики.

## Примеры контрастных обучающих строк

### Сантехника vs Кровля

```python
("соседи сверху заливают, течет с потолка в ванной", "Сантехника")
```

## Известные ограничения v1.0.0

- Модель не предсказывает категорию `Другое`, если она не входила в обучение.
- Категория `Системы ДУ и ППА` может требовать дополнительного дообучения.
- На CPU обработка больших Excel-файлов может занимать длительное время.
- Качество зависит от согласованности исходной разметки.
- В реальных обращениях часто встречаются смешанные проблемы, где одна заявка может относиться сразу к нескольким категориям.
- Уверенность модели не всегда является гарантией правильного ответа: уверенные ошибки нужно анализировать отдельно.

## Практическая интерпретация результата

Если общий accuracy ниже ожидаемого, сначала проверьте:

1. Есть ли в исходной таблице категории, которых нет в модели.
2. Есть ли лишние пробелы в названиях категорий.
3. Какие пары ошибок находятся в `error_pairs.xlsx`.
4. Какие ошибки с высокой уверенностью находятся в `high_confidence_errors.xlsx`.
5. Нет ли в исходной таблице спорной или непоследовательной разметки.

Для реальной оценки модели полезно смотреть не только общий accuracy, но и:

```text
macro F1
weighted F1
recall по слабым категориям
частые пары ошибок
ошибки с высокой уверенностью
accuracy без неизвестных модели категорий
```

## Назначение проекта

Проект предназначен для локального анализа и доработки модели классификации обращений ЖКХ.

Основной сценарий использования:

```text
1. Получить Excel-выгрузку обращений.
2. Запустить модель на столбце "Описание проблемы".
3. Сравнить результат с исходной категорией.
4. Найти слабые категории и частые ошибки.
5. Подготовить дополнительные обучающие примеры.
6. Переобучить модель.
7. Повторить проверку на новой выгрузке.
```
